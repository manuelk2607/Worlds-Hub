# Worlds language preference contract

Worlds Hub supports the canonical language codes `de` and `en`. German is the fallback. New Worlds applications, including Music-Worlds, should use the same codes and a namespaced, key-based catalogue with one file per language.

## Browser and URL contract

- Public English pages use `/en/...`; existing German URLs remain unchanged.
- On the first visit, `Accept-Language` is negotiated and unsupported languages fall back to German.
- A manual choice is stored under `localStorage["worlds.locale"]` and in the host-only `__Host-worlds-locale` cookie.
- Cookies are never shared between separate `workers.dev` hosts. Each application keeps its own host-only preference.
- A language switch updates marked UI text, metadata, links and `lang` in place. It must preserve forms, game state and the signed OAuth query.
- User-created content is never passed through the UI translation catalogue.
- Music-Worlds already uses `de` and `en`, separate key-based catalogues and a DE/EN switch. Its existing device preference uses `mw-language` on the Music-Worlds origin.

## Identity contract

- OIDC authorization requests may send the standard `ui_locales=de|en` hint.
- A verified Worlds subject can store `locale` in the central preference service. The key is `(issuer, subject)`; email addresses are not identifiers.
- The Hub reads the signed-in profile on load. An existing profile preference takes precedence over the device default. If no profile value exists, the Hub initializes it from the device preference with a conditional insert. A manual change on the current page wins over an in-flight profile response.
- Each project may read a verified locale claim in a future identity profile, but must validate issuer and subject before using it. Locale never grants roles or project access.
- Project sessions, databases and authorization remain independent. Language sync never relays cookies or bearer tokens between applications.
- `ui_locales` is a display hint for sign-in. Automatic profile synchronization between the Hub and Music-Worlds requires a verified identity claim or an authenticated service contract.

Dates, times and numbers use `Intl` with `de-DE` or `en-GB`. Applications may use the browser time zone for display while retaining ISO timestamps in data attributes or APIs.
